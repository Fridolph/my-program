# VitePress 人工元数据覆盖层任务拆解

## 背景

第二阶段已经打通了 demo 自动扫描、页面生成、侧边栏同步和预览链路，但站点内容质量仍受限于历史 HTML 的元信息质量。

当前自动提取存在三个明显问题：

1. 很多 demo 没有有效 `meta description`，最终落成了泛化描述。
2. 一些标题直接沿用了旧文件名或英文 demo 标题，不适合作为站点目录名称。
3. 中文目录经过兜底 slug 化后，详情页路由可用但不够友好。

因此下一阶段优先做“人工元数据覆盖层”，让站点在保留自动发现能力的同时，支持人工校准关键 demo 的标题、描述、标签和路由名。

## 本轮目标

- 建立一层稳定的 metadata override 机制。
- 支持按 demo 源路径覆盖标题、描述、标签、难度和 slug。
- 为首批高价值或质量较差的 demo 补人工元数据。
- 保持自动扫描为默认路径，避免站点退回手工维护模式。

## 任务拆解

### T1：定义覆盖层数据结构

- 新增单独的 overrides 文件。
- 以 `public/` 下的相对 HTML 路径作为键。
- 允许覆盖 `title`、`description`、`tags`、`difficulty`、`slug`。

### T2：接入 registry 合并逻辑

- 扫描 HTML 后先生成默认 metadata。
- 再按相对路径查找人工覆盖项并合并。
- 对 slug 冲突与未知路径做校验，避免生成失真。

### T3：补第一批人工 metadata

优先处理下面几类：

- 自动描述退化成“示例。”的 demo。
- 中文目录导致 slug 过于机器化的 demo。
- 标题和站点上下文不匹配的 demo。
- 首屏和分类页更容易被看到的 demo。

### T4：验证生成结果

- 重新生成所有页面。
- 检查分类页、首页精选和 sidebar 中的标题是否改善。
- 抽样检查被覆盖 demo 的详情页 slug 是否更新且无冲突。

### T5：沉淀开发记录

- 记录为什么需要 metadata 覆盖层。
- 记录当前边界：仍然以自动扫描为主，人工覆盖只修关键项。
- 为后续“目录级覆写”或“可视化配置后台”留下入口。

## 验收标准

- registry 能稳定消费人工 metadata。
- 覆盖项路径错误会在生成阶段直接报错。
- slug 冲突会被校验出来。
- 首批关键 demo 的标题、描述和链接明显改善。
- 文档和技术博客同步补齐。
