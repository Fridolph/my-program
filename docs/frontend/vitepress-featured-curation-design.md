# VitePress 首页精选编排详细设计

## 设计目标

前两轮已经把 metadata 体系拆成了默认提取、目录 preset 和单文件 override。

这轮继续沿着这条线往前走：

- metadata 不只用来修标题和描述。
- metadata 还应该参与首页内容编排。

首页精选如果继续靠“截前几个”，它只是一个技术产物；只有当精选本身可配置、可解释、可排序时，它才更像一个真正的展示入口。

## 数据结构

在 metadata 中新增 `featured` 字段。

推荐结构：

```js
featured: {
  priority: 90,
  reason: '视觉冲击强，适合作为首页吸引入口。'
}
```

### 字段职责

- `priority`：数值越大，越靠前。
- `reason`：展示在首页精选卡片上的推荐理由。

## 合并位置

`featured` 与其他 metadata 一样，参与现有合并链路：

1. 自动提取默认 metadata
2. 目录 preset
3. 单文件 override

这样目录 preset 可以为一个系列批量设置精选信息，单文件 override 仍然能覆盖或修正单个 demo。

## 编排规则

### 1. 首页优先使用显式精选

先收集所有带 `featured` 的 demo，并按 `priority` 倒序排序。

### 2. 精选不足时再兜底补足

如果显式精选数量不足首页目标数量，再从剩余 demo 中按稳定顺序补足。

### 3. 首页卡片展示推荐理由

推荐理由是精选区和普通列表最大的差异点，它能说明“为什么是这个 demo”，而不是只展示一个标题和链接。

## 校验机制

为了避免 featured 变成随意堆字段，需要最基本的结构校验：

- `priority` 必须是有限数字。
- `reason` 如果存在，必须是非空字符串。

## 首批精选策略

本轮不追求一次做复杂算法，只先建立一份质量可控的首批精选列表。

挑选原则：

- 优先视觉表现强的 demo。
- 尽量覆盖多个分类。
- 尽量避免首页出现过长、过技术化、缺少代表性的条目。

## 后续扩展方向

如果这层规则跑稳，下一步可以继续做：

1. 增加分类配额，控制首页精选分布。
2. 支持首页 Hero 与精选卡分层。
3. 接入截图、封面图、推荐标签等更丰富的展示字段。
