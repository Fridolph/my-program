# VitePress 重构进度盘点

## 当前状态

截至 2026-03-12，站点已经完成第一轮从静态导航页到 VitePress 展示站的迁移，现状如下：

- 已引入 `docs-site/`，站点可独立构建与部署。
- 已落地自定义主题、Demo 卡片和预览组件。
- 已接入 GitHub Pages 工作流。
- 已具备 demo 页面自动生成的基础能力。

## 已暴露的问题

第一轮重构已经证明方向可行，但当前实现还停留在“能展示”的阶段，距离“可持续维护”还有明显差距：

1. 生成链路只覆盖了部分 demo，分类页与详情页数量明显少于 `public/` 实际内容。
2. 侧边栏仍是空配置，分类导航没有和真实内容同步。
3. `build` 之前没有强制执行生成脚本，存在站点内容和源文件脱节的风险。
4. 预览组件在刷新和二次挂载时容易出错，对脚本型 demo 的支持也不完整。
5. 缺少一套把“进度盘点 -> 里程碑 -> 详细设计 -> 开发验证”串起来的文档。

## 本轮盘点结论

这次重构的下一阶段重点，不是继续堆页面样式，而是先把“内容发现、页面生成、导航同步、预览稳定性”这条主链路打通。

换句话说，第二阶段的目标应当是：

> 让 VitePress 站点从一次性重构成果，升级为可持续迭代的 demo 编排系统。

## 里程碑建议

### M1：守住生成链路

- 扫描 `public/` 全量 HTML demo。
- 自动生成分类页、详情页、首页摘要。
- 让生成结果成为 `dev` / `build` 的前置步骤。

### M2：补齐站点导航

- 生成真实侧边栏。
- 保证导航与 demo 数量、路由一致。
- 为分类页提供清晰统计信息。

### M3：稳住预览体验

- 修复 Shadow DOM 预览的重复挂载问题。
- 处理相对路径资源重写。
- 让依赖脚本的 demo 在预览容器内尽量可运行。

### M4：建立维护文档

- 输出里程碑规划。
- 输出任务拆解与优先级。
- 输出详细设计文档与开发记录。

## 本轮实际落点

本轮开发优先覆盖 M1、M2、M3 的核心路径，并同步补齐 M4 文档。

## 下一阶段焦点

在生成链路跑通之后，当前最值得优先补的是人工 metadata 覆盖层。

原因很简单：

- 站点已经能纳入内容，但内容还不够好读。
- 自动提取对旧 demo 的标题、描述和 slug 质量帮助有限。
- 如果不补这层，分类页和 sidebar 很容易继续呈现“机器生成感”。

因此下一轮开发优先级调整为：

1. 增加 metadata override 机制。
2. 修首批高价值 demo 的标题、描述、标签与 slug。
3. 验证生成链路在人工覆盖存在时仍然稳定。

## Metadata 层的下一步

人工 metadata 覆盖层已经证明方向正确，但目前仍有不少系列目录在重复写相似配置。

因此接下来的优化重点是：

1. 补目录级 metadata preset。
2. 把系列共性从单条 override 中抽出来。
3. 继续把 metadata 结构从“配置表”整理成“分层系统”。

## 首页编排的下一步

metadata 层完成 preset 和 override 分层后，下一步自然就是把这些信息用于首页精选编排。

当前优化重点：

1. 给 demo 增加 featured metadata。
2. 用优先级和推荐理由替代顺序截取。
3. 让首页更像策展入口，而不是列表裁切结果。

## 首页视觉策展的下一步

首页精选已经有了 metadata 编排能力，下一步自然是让这些精选条目具备更明确的视觉入口。

当前优化重点：

1. 增加 cover metadata。
2. 让首页精选卡片显示封面区。
3. 在不引入复杂截图流水线的前提下，先把首页展示感补起来。

## 首页封面资源化的下一步

cover metadata 已经让首页精选具备了封面层，下一步自然是把这些封面从样式片段推进到可复用资源。

当前优化重点：

1. 生成 SVG 封面资源。
2. 让首页优先消费 image cover。
3. 为后续分类页和分享图复用留出资源基础。
