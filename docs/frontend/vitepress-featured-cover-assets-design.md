# VitePress 首页精选封面资源化详细设计

## 设计目标

上一轮已经建立了 cover metadata 和首页封面区，但封面目前还是即时渲染的渐变背景。

这一轮的目标是把封面继续推进成“可复用资源”：

- 首页不只是在样式层渲染 cover。
- 封面本身要能成为独立资产。
- 但又不引入沉重的截图流水线。

因此最合适的当前解法是：

> 用 metadata 驱动生成 SVG 封面资源。

## 为什么选 SVG

相比位图截图，SVG 更适合当前阶段：

- 文本和图形都是声明式，可由脚本直接生成。
- 不依赖浏览器截图环境。
- 资源体积小，提交和构建成本可控。
- 后续如果用于首页、社交卡片、分类推荐，也更容易复用。

## 目录与生成入口

封面资源输出到：

- `public/featured-covers/`

这样生成后的资源可以直接被站点访问，也能跟随现有 public 复制流程进入最终构建产物。

生成入口放在现有页面生成链路里，保证：

- 本地 `generate` 时同时产出 Markdown 和 SVG 封面
- `prebuild` 时自动生成封面资源

## metadata 结构

现有 `cover` 结构继续沿用，并增加一个资源化约定：

- 如果 `cover.type === 'gradient'` 且 demo 是 featured，则脚本会同时生成一张 SVG 封面图。
- 生成后首页可优先使用 `/featured-covers/<demo-id>.svg` 作为 `image` 封面。

这意味着：

- metadata 仍然是唯一配置源。
- 封面资源只是 metadata 的派生产物。

## 生成逻辑

每张 SVG 封面包含：

- 背景渐变
- 分类标签
- 短标题
- demo 主标题
- 标签 chips
- 轻量装饰图形

这样既保持生成成本低，也能比纯渐变背景更像真实封面。

## 首页渲染策略

### 1. 首页优先使用 image cover

如果 demo 存在生成后的 cover 资源，则首页用 `image` 模式渲染。

### 2. 资源缺失时回退到 gradient

如果某个封面生成失败，首页仍然可以退回当前 gradient 模式，不影响构建通过。

## 风险与边界

### 风险 1：SVG 设计过重会让资源生成变复杂

所以本轮封面只追求“有辨识度的轻量海报”，不追求复杂插画。

### 风险 2：首页和封面配置可能逐渐耦合过深

因此必须坚持：

- metadata 负责表达意图
- 生成脚本负责产出资源
- 首页只消费结果

## 后续扩展方向

如果 SVG 资源化方案跑稳，下一步可以继续做：

1. 为 cover 增加更复杂的模板类型。
2. 把封面资源复用到分类页推荐区。
3. 结合真实截图或静态缩略图形成混合封面系统。
