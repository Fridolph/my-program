# VitePress 首页精选编排任务拆解

## 背景

目录级 metadata preset 已经把系列共性整理出来了，但首页精选区仍然存在一个明显问题：

- 当前精选 demo 只是按分类顺序截取前几项。
- 首页展示结果更多反映的是数据排列顺序，而不是内容价值。
- 一些描述过长或不够代表性的 demo 仍可能出现在首页。

所以这一轮要继续把 metadata 从“可读”推进到“可编排”。

## 本轮目标

- 让首页精选从固定截取，升级为 metadata 驱动编排。
- 支持为 demo 标记精选优先级与推荐理由。
- 保持没有精选 metadata 时的安全兜底。
- 让首页展示更像策展页，而不是默认列表截断。

## 任务拆解

### T1：定义精选 metadata 结构

要求：

- 支持开关是否进入首页精选。
- 支持优先级排序。
- 支持推荐理由文案。

### T2：接入 registry

- 在 metadata 合并链路里支持 featured 字段。
- 在最终 demo 数据中保留精选信息。
- 为精选字段增加基本校验。

### T3：实现首页编排规则

- 首页优先展示显式标记的精选 demo。
- 按优先级排序。
- 若精选数量不足，使用可预测规则补足。
- 避免首页被单一分类完全占满。

### T4：补首批精选配置

优先挑选：

- 视觉表现强、适合首页首屏吸引的 demo。
- 代表不同分类能力的 demo。
- 说明文案已经较成熟、适合展示的 demo。

### T5：更新首页文案与样式

- 在精选卡片中展示推荐理由。
- 让首页文案体现“策展式推荐”而不是“随机挑选”。

### T6：沉淀文档与开发记录

- 说明为什么首页不能继续依赖顺序截取。
- 说明精选 metadata 和 preset / override 的关系。
- 记录当前精选规则的边界与后续可扩展点。

## 验收标准

- 首页精选改为 metadata 驱动。
- 精选 demo 按优先级排序。
- 精选卡片能显示推荐理由。
- 生成与构建通过。
- 文档和技术博客同步补齐。
