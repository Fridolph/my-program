# 2026-03-28 · 让 quick start 的下一步开始对齐角色与阶段

## 背景

M21 完成之后，quick start 已经开始告诉用户：

- 下一步该先补哪一类
- 为什么这一步值得先补

这让 quick start 不再只停在“下一步去哪”。

但新的缺口也马上变得很清楚：

> 当用户已经知道下一步更像补结构、补反馈、补首屏氛围还是补局部动效之后，他还是不容易判断，这个判断对当前角色和当前阶段到底意味着什么。

这就是 M22 要继续补上的一层语义。

## 这一轮怎么推进

这一轮继续按 Dao 节奏推进：

1. 先确认 M22 仍然沿着 quick start 主链路走，而不是另起新系统。
2. 梳理当前已经具备的字段：`audiences`、`stages` 和 `followUpPlans`。
3. 决定这一轮不新增重字段，而是直接在生成链路里做静态交叉聚合。
4. 让角色页和阶段页开始表达常见推进类型。
5. 让推进类型页开始表达常见角色与常见阶段。
6. 让 quick start 详情页开始出现“从角色 / 阶段继续判断”的回看入口。
7. 同步把这层交叉提示接回首页、discover 和 quick start 总览。
8. 开发完成后跑 `pnpm docs:generate`、`pnpm docs:build`、`pnpm docs:check`。

## 关键判断

### 1. 这一轮不做新推荐系统，只做静态交叉解释

M22 没有引入动态推荐，也没有引入用户状态。

因为当前最稳定的问题不是“还要不要更聪明地推荐”，而是：

- 现在已经有了下一步建议
- 但解释还不够贴近用户当前的角色和阶段

所以这一轮只补最稳定的一层静态交叉表达。

### 2. 继续复用 quick start 主链路，不新增重字段

这一轮没有往 `quickStartGuides` 里继续堆更多字段。

而是继续复用已经存在的三层语义：

- `audiences`
- `stages`
- `followUpPlans`

再由生成链路把它们交叉起来。

这样做的好处很直接：

- 数据源仍然集中
- 生成链路仍然统一
- 页面解释力提升了，但内容系统没有变重

### 3. 先补解释力，再决定要不要长出新入口层级

这一轮没有新增复杂的三维矩阵路由。

因为当前更重要的不是“入口越多越好”，而是先让已经存在的页面更会解释：

- 角色页不只回答从哪里开始，也开始回答下一步更常补哪一类
- 阶段页不只回答什么时候开始，也开始回答这个阶段更常往哪里接
- 推进类型页不只回答先补什么，也开始回答这一步更像谁、通常在什么时候补

## 这轮代码上发生了什么

### 角色页和阶段页开始表达常见推进类型

这一轮把 quick start 的 follow-up 继续接回：

- 角色页
- 阶段页

现在用户不只会看到当前角色 / 阶段有哪些起步线，也会继续看到：

- 这个视角下更常见的下一步推进类型
- 对应的常见推进顺序

这让角色和阶段页面开始具备更明确的继续推进语义。

### 推进类型页开始表达常见角色与常见阶段

这一轮也把推进类型页继续补强。

现在用户进入某种推进类型之后，不只会看到：

- 当前类型下有哪些常见推进顺序

还会看到：

- 这类推进更常见于哪些角色
- 这类推进更常见于哪些阶段

这样“补内容入口”“补反馈节奏”这些类型，就开始不只是抽象分类，而更像可判断的实际推进方向。

### quick start 详情页开始支持从角色 / 阶段继续判断

这一轮还把交叉判断继续接回了 quick start 详情页本身。

现在用户在看完“下一步建议”和“推进类型”之后，还可以继续从：

- 当前角色视角
- 当前项目阶段

回看对应的 quick start 聚合页。

这意味着 quick start detail 页开始具备：

- 下一步去哪
- 下一步属于哪一类
- 这个判断对当前角色 / 阶段意味着什么

这三层连在一起的能力。

### 首页、discover 和 quick start 总览一起补了交叉提示

为了不把这层判断只关在 detail 页里，这一轮还把交叉提示同步接回了入口层。

现在用户在：

- 首页
- discover
- quick start 总览

都能更早意识到：

> 下一步不只可以按类型看，也可以回到当前角色和阶段继续判断。

## 自测

这一轮继续使用统一闭环：

```bash
pnpm docs:generate
pnpm docs:build
pnpm docs:check
```

除此之外，我额外重点核对了四件事：

1. quick start 详情页是否已经出现角色 / 阶段继续判断入口。
2. 角色页与阶段页是否已经开始显示常见推进类型。
3. 推进类型页是否已经开始显示常见角色与常见阶段。
4. 首页、discover 和 quick start 总览是否已经出现交叉提示。

## 这一轮的结论

M22 最重要的变化，不是多了几个新卡片，而是：

> 当前 quick start 已开始具备静态交叉判断能力，能把“继续推进”进一步解释成更贴近角色视角与项目阶段的下一步判断。

这会让 quick start 更像一条持续陪用户往前走的判断链，而不只是不断加入口标签。

## 后续方向

M22 到这里已经完成。后续自然还可以继续推进，例如：

1. 继续补“当前先不上什么”的反向推进语义。
2. 继续把角色 / 阶段 / 推进类型之间的取舍关系讲得更清楚。
3. 在静态交叉判断稳定之后，再评估是否需要更细的路线编排。
