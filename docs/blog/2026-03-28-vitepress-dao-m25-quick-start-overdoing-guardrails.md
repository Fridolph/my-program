# 2026-03-28 · 让 quick start 开始提醒哪里最容易做过头

## 背景

M24 完成之后，quick start 已经开始告诉用户：

- 当前该补什么
- 当前先不上什么
- 为什么当前这样排顺序

这让 quick start 的判断链已经更完整了。

但新的缺口也很快变得很清楚：

> 当用户已经知道怎么排顺序之后，他还是不容易判断，这条线最容易做过头的地方在哪里。

这就是 M25 要继续补上的语义。

## 这一轮怎么推进

这一轮继续按 Dao 节奏推进：

1. 先确认 M25 仍然沿着 quick start 主链路走，不新增复杂系统。
2. 梳理当前已有的 follow-up、defer 和 tradeoff 语义，确认还缺一层 guardrail 提醒。
3. 定义新的轻量字段：`overdoWarnings`。
4. 让 quick start 详情页开始表达“当前最容易做过头的地方”。
5. 让角色页、阶段页与推进类型页开始聚合常见过度设计提醒。
6. 把这层轻量 guardrail 提示接回首页、discover 与 quick start 总览。
7. 开发完成后跑 `pnpm docs:generate`、`pnpm docs:build`、`pnpm docs:check`。

## 关键判断

### 1. 这一轮不做复杂风险系统，只补最稳定的 guardrail 提醒

M25 没有开始做评分系统，也没有引入更复杂的风险矩阵。

因为当前最稳定的问题不是“风险判断不够细”，而是：

- 用户知道方向了
- 但还不知道哪里最容易失控

所以这一轮只补最稳定的一层过度设计提醒。

### 2. 继续写回 quick start 主链路，不另建新模型

这一轮没有另外建“设计风险系统”。

而是继续把提醒写回 `quickStartGuides`：

- `overdoWarnings`

每条提醒都只回答两件事：

- 哪个方向最容易做过头
- 为什么这个方向最容易失控

这样 quick start 的判断链仍然是一条主线，不会突然变成另一套独立系统。

### 3. “哪里最容易失控”比再多一条建议更能帮助用户收手

M20 解决的是下一步去哪。
M21 解决的是下一步属于哪一类。
M22 解决的是这一步对角色 / 阶段意味着什么。
M23 解决的是当前先不上什么。
M24 解决的是为什么这样取舍。

M25 继续往前推进一层：

- 当前最容易做过头的地方

这会让 quick start 不只是不断告诉用户该做什么，也开始提醒用户什么时候该踩刹车。

## 这轮代码上发生了什么

### quick start 统一补了过度设计提醒字段

这一轮为 quick start 统一补齐了：

- `overdoWarnings`

这样每条 quick start 不只会表达：

- 下一步补什么
- 当前先不上什么
- 为什么这样取舍

也开始表达：

- 哪个方向最容易做过头
- 为什么这个方向最容易失控

### quick start 详情页开始表达“当前最容易做过头的地方”

这一轮最直观的变化，是 quick start detail 页新增了新的 guardrail 区块：

- 当前最容易做过头的地方

这个区块会直接把当前最容易失控的方向和提醒说明放在一起，帮助用户在推进时更早收手。

### 角色页、阶段页和推进类型页开始聚合 guardrail 提示

这一轮还把过度设计提醒继续接回聚合页。

现在在：

- 角色页
- 阶段页
- 推进类型页

用户都能看到一层更轻量的常见 guardrail 提示，而不只是继续加入口判断。

### 首页、discover 与 quick start 总览一起接入了轻量提醒

为了不把这层提醒只放在 detail 页里，这一轮也把“做过头”的提示接回了入口层。

现在用户在：

- 首页
- discover
- quick start 总览

都能更早看到一些典型 guardrail，例如：

- 首屏方向最容易在氛围层做过头
- 列表页最容易在局部动效上做过头
- 阅读反馈页最容易把提示系统做成两套竞争反馈
