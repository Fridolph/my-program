# 2026-03-20 · 让 quick start 开始按角色和阶段分层

## 背景

M18 完成之后，quick start 已经不只告诉用户：

- 从哪里开始
- 开始之后先做什么
- 这条线值不值得现在做

但新的缺口也变得很清楚：

> 用户已经知道某条 quick start 适合谁，却还不能按自己的角色和项目当前阶段，直接聚合看到更贴近自己的起步线。

这就是 M19 的起点。

## 这一轮怎么推进

这一轮继续按 Dao 节奏推进：

1. 先定义 M19 的目标、边界和分层模型。
2. 梳理 quick start 现有字段里哪些已经在隐含表达角色和阶段。
3. 再补 `audiences` 和 `stages` 两层静态元数据。
4. 接着生成角色索引页、角色详情页、阶段索引页和阶段详情页。
5. 然后把 quick start 总览、discover、首页和 discover 侧边栏一起接上分层入口。
6. 开发完成后跑 `pnpm docs:generate`、`pnpm docs:build`、`pnpm docs:check`。
7. 自测通过后，再回写设计、任务、进度、路线图和开发笔记。

## 关键判断

### 1. 这一轮只做静态分层，不做动态推荐

M19 没有引入用户画像，也没有引入动态推荐逻辑。

因为当前阶段最稳定、也最容易维护的，是两层静态分组：

- 按角色开始
- 按阶段开始

它们已经足够帮助用户缩小入口范围，但又不会把 quick start 拉成一套复杂推荐系统。

### 2. 分层信息不能只放在字段里

如果 `audiences` 和 `stages` 只是详情页里两行说明，用户还是要先点进去之后才知道这条线是不是更贴近自己。

所以这一轮没有停在字段补齐，而是继续把字段推进成真正可访问的入口页：

- `/discover/quick-start/roles/`
- `/discover/quick-start/roles/:slug`
- `/discover/quick-start/stages/`
- `/discover/quick-start/stages/:slug`

这样分层才会真正变成浏览路径，而不是隐藏说明。

### 3. quick start 继续承担“帮用户缩短起步判断”的职责

M16 解决的是“从哪里开始”。
M17 解决的是“开始之后先做什么”。
M18 解决的是“值不值得现在做”。

M19 则继续往前推进一层：

- 站在谁的视角开始
- 处在项目哪个阶段开始

这让 quick start 更像一条轻量起步线，而不只是问题清单。

## 这轮代码上发生了什么

### quick start 统一补了角色与阶段字段

这一轮为现有 quick start 统一补齐了：

- `audiences`
- `stages`

这样每条 quick start 不只回答“适合什么页面”，也开始回答：

- 更贴近谁的工作视角
- 更适合项目当前哪个阶段

### 新增角色页与阶段页

这一轮新生成了两层聚合页：

- 角色索引页与角色详情页
- 阶段索引页与阶段详情页

生成后的详情页会继续回流到：

- quick start
- spotlight
- scene
- demo
- 开发笔记

这让分层页不是新的孤岛，而是继续复用现有内容主链路。

### quick start 详情页开始支持角色 / 阶段回看

这一轮还把 quick start 详情页做了补强。

现在用户在一条 quick start 内，不只会看到适合谁和当前阶段，还能直接回跳到对应的角色页与阶段页，继续扩大浏览范围。

### 首页与 discover 开始显式暴露分层入口

这一轮同步把入口层表达也一起收口了。

现在除了 quick start 总览页，以下位置也开始暴露分层入口：

- 首页内容入口区
- discover 页 quick start 区
- discover 侧边栏

这样用户不需要先知道 quick start 详情结构，第一眼就能发现“按角色开始 / 按阶段开始”这两条新入口。

## 自测

这一轮继续使用统一闭环：

```bash
pnpm docs:generate
pnpm docs:build
pnpm docs:check
```

除此之外，我额外人工抽查了四件事：

1. 角色索引页与阶段索引页是否稳定生成。
2. 角色 / 阶段详情页是否能回流到 quick start、spotlight、scene 与 demo。
3. quick start 详情页是否已经出现角色 / 阶段回看入口。
4. 首页、quick start 总览和 discover 是否已经显式暴露分层入口。

这轮自测通过，说明 M19 已经完成了从“通用问题入口”到“按角色 / 按阶段进入”的闭环。

## 这一轮的结论

M19 最重要的变化，不是多了几页聚合页，而是：

> 当前 quick start 已开始具备静态分层能力，能更贴近不同用户视角和不同项目阶段。

这对内容站很重要。

因为真正有效的入口，不只是把内容列出来，而是先帮用户缩短“我是不是该从这里开始”的判断距离。

M19 把这件事继续往前推了一步。

## 后续方向

M19 到这里已经完成。后续自然还可以继续推进，例如：

1. 继续补更细的角色视角，比如设计侧、内容侧、工程侧更明确的起步线。
2. 继续补更细的阶段判断，比如验证前、方案成型后、上线复盘前的不同入口。
3. 在分层能力稳定之后，再评估是否需要更强的推荐、筛选或任务编排层。
