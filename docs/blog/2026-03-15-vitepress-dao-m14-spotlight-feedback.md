# 2026-03-15 · 让专题路线真正回流到 demo 详情页

## 背景

M13 完成之后，站点已经有了专题路线。

用户可以从首页、discover 和专题路线索引页进入更高层的问题入口，这一步已经把“scene 很多”推进到了“问题路线更清楚”。

但继续往下看时，新的断点也很明显：

> 专题路线已经建立了，可一旦用户点进 demo 详情页，这条路线感就又断掉了。

也就是说，spotlight 已经存在，但它还没有真正反过来提升 demo 详情页的解释力。

这就是 M14 要解决的问题。

## 这一轮怎么推进

这一轮继续按同一条 Dao 节奏推进：

1. 先明确 M14 的目标、边界和业务流。
2. 梳理 demo 与 spotlight 的回流断点。
3. 再把相关专题路线区块接入 demo 详情页模板。
4. 接着补一批 spotlight 内长尾 demo 的结构化深描内容。
5. 开发完成后跑 `pnpm docs:check`，确认生成、构建和校验都通过。
6. 自测通过后，再回写设计、任务、进度和开发笔记。

## 关键判断

### 1. spotlight 不能只停留在入口层

如果专题路线只存在于 discover 页，它的作用就还是“帮助进入”。

但 M14 要解决的是另一件事：

> 用户已经进入具体 demo 后，路线还能不能继续解释这个 demo 为什么值得看。

只有这一步成立，spotlight 才不只是一个入口集合，而是开始成为 demo 页的上层语境。

### 2. 先补路线内长尾 demo，而不是平均补全站

这一轮没有平均去补所有案例。

优先补的是已经进入 spotlight、但内容解释还偏弱的一批长尾 demo，例如：

- `milestone-gallery-1`
- `stacked-profile-gallery`
- `split-panel-gallery`
- `gradient-background-gallery`
- `css-transform-gallery`
- `single-element-loading`
- `mirror-menu`
- `other-card-change-layout`

这样做的好处很直接：

先把已经进入路线的详情页质量拉起来，比平均铺到全站更有效。

### 3. 继续复用 metadata 主链路

这一轮没有新建手写 Markdown 详情页分支。

深描内容继续通过 metadata override 回写，生成链路继续统一输出 demo 页面。

这样后续如果还要继续补长尾案例，仍然可以沿着同一条主链路扩。

## 这轮代码上发生了什么

### demo 模板开始识别相关专题路线

这一轮在生成脚本里增加了 demo 与 spotlight 的匹配逻辑，综合判断：

- 当前 demo 是否被路线直接点名
- 当前 demo 的 scene 是否命中路线覆盖范围
- 当前 demo 是否进入路线的优先推荐区

生成后，demo 详情页开始出现“相关专题路线”区块。

这一步把路线页到 demo 页的单向流转，补成了真正的双向回流。

### 长尾 demo 开始具备统一的结构化内容骨架

这一轮补齐的字段统一是：

- `whyRead`
- `implementationNotes`
- `whenToUse`
- `adaptationTips`

它们解决的是同一个问题：

> 用户不只知道“这里有个 demo”，还知道“为什么要看、怎么拆、什么时候用、迁移时注意什么”。

这让 demo 页比之前更像文档节点，而不只是原始页面入口说明。

## 自测

这一轮继续使用统一闭环：

```bash
pnpm docs:check
```

除此之外，我额外人工抽查了几类页面：

1. `single-element-loading` 是否已出现相关专题路线。
2. `milestone-gallery-1`、`split-panel-gallery` 是否已显示结构化深描内容。
3. `other-card-change-layout` 是否能从详情页回流到卡片专题路线。
4. 路线页、demo 页、sitemap 和 release 快照是否仍保持生成稳定。

这轮自测通过，说明 M14 已经完成了从“有 spotlight”到“spotlight 反向增强 demo 详情页”的闭环。

## 这一轮的结论

M14 最重要的变化，不是“又补了几段文案”，而是：

> 当前专题路线已经开始真正参与 demo 详情页的解释，而不只是承担站点入口组织。

这是内容站继续往前长的重要一步。

因为内容一旦继续增多，真正重要的不是只有更多入口，而是：

- 入口能不能解释详情页
- 详情页能不能回到更高层路线
- 路线和案例之间能不能形成稳定的语义闭环

M14 把这件事往前推进了一步。

## 后续方向

M14 到这里已经完成。后续自然还可以继续推进，例如：

1. 继续补更多 spotlight 路线，扩大长尾 scene 的承接密度。
2. 继续把深描内容铺到更多重点 demo，逐步拉齐详情页质量。
3. 在路线与详情页关系更稳定之后，再评估是否要补更强的推荐或检索层。
