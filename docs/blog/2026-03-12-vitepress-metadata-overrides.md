# 2026-03-12 · 给 VitePress demo 站补一层人工元数据覆盖

## 起因

上一轮我把 demo 站的自动扫描和页面生成链路打通了，但很快遇到一个更偏“内容质量”的问题。

站点已经能把 `public/` 里的 HTML demo 全量纳入进来，但很多历史 demo 自带的信息并不适合直接拿来做文档站内容：

- 有些页面没有描述，最后只能退化成泛化文案。
- 有些标题其实更像文件名，而不是给用户看的条目标题。
- 中文目录在兜底 slug 化后虽然可用，但 URL 不够友好。

这说明自动化已经解决了“有没有”，下一步要解决的是“好不好读”。

## 这次判断

这轮不应该回退到手工维护所有 Markdown，而是应该在自动扫描主链路上叠一层人工修正能力。

也就是说：

> 自动扫描负责广覆盖，人工 metadata 覆盖负责精修关键 demo。

这个边界一旦立住，后面的实现就比较清晰了。

## 实现方式

### 1. 新增 metadata overrides 文件

我加了 `docs-site/scripts/demo-metadata-overrides.mjs`，以 `public/` 下的相对 HTML 路径为 key。

这样做的好处是：

- 路径和源文件一一对应。
- 即使标题和 slug 以后继续调整，override 仍然稳定。
- 不会把覆盖层绑死在当前某一版生成结果上。

### 2. 在 registry 里做合并

`demo-registry.mjs` 现在会先生成默认 metadata，再按相对路径合并人工覆盖项。

当前支持覆盖的字段有：

- `title`
- `description`
- `tags`
- `difficulty`
- `slug`

其中 `slug` 只用来影响详情页路由，不会反过来污染源路径。

### 3. 给覆盖层补校验

为了避免 override 文件悄悄失效，我顺手加了两层保护：

- override 指向了不存在的 HTML 路径时，生成阶段直接报错。
- 两个 demo 覆盖出相同 slug 时，生成阶段直接报错。

这样这层覆盖机制才能长期可维护，而不是越写越乱。

## 首批修了什么

这轮没有强行把所有 demo 全部人工精修，而是优先处理了三类：

1. 描述明显退化成“示例。”的 demo。
2. 中文目录导致 slug 很难读的 demo。
3. 首页和分类页里比较容易被看到的 demo。

比如：

- `hover-transition/自制表情/index.html` 现在会生成更友好的 `emoji-face` 路由。
- `canvas/change-background/index.html` 现在不再保留原始文件名式标题。
- 一批进度条、卡片、菜单、布局示例补上了更接近真实用途的描述和标签。

## 我学到的点

这次最值得记住的一点是：

> 文档站里的内容质量问题，很多时候不是渲染层的问题，而是 metadata 层的问题。

只要 metadata 仍然混乱，哪怕页面结构做得再完整，最终看起来也会像“自动生成出来的一堆页面”。

所以这层人工覆盖虽然小，但它本质上是在补“站点可读性”的基础设施。

## 自测

这轮我还是按生成和构建两层做自测：

```bash
cd docs-site
node scripts/generate-demo-pages.js
npm run build
```

重点检查：

- override 路径是否都能命中。
- 生成后的路由是否有重复。
- 首页、分类页和 sidebar 中的标题是否明显改善。

## 后续

如果这层机制跑稳，下一步可以继续做两件事：

1. 增加目录级别的 metadata 预设，减少同系列 demo 的重复配置。
2. 给精选 demo 增加截图、推荐理由和排序权重。
