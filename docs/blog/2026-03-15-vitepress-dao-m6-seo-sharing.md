# 2026-03-15 · 让站点开始具备被搜索与被分享的基础能力

## 背景

走到 M5 之后，站点内部的浏览结构已经比较完整了：

- 分类路径
- 内容路径
- 多维导航路径

用户在站内已经可以比较顺地从首页走到分类、走到 demo、走到开发笔记，再从内容回到案例。

但如果从站点外部看，还差一层很关键的基础设施：

> 站点虽然能被访问，但还没有系统地告诉搜索引擎和分享系统“我是谁、我有哪些页面、应该怎么理解我”。

所以 M6 这一轮，我没有继续加内容类型，也没有继续扩浏览入口，而是先补：

> 让站点开始具备被搜索、被理解、被分享的基础能力。

## 这一轮怎么做

这一轮继续严格按 Dao 节奏推进：

1. 先定义 M6 的目标、边界和业务流。
2. 再明确站点级 SEO 与分享要补哪些资产。
3. 然后把这些能力接回现有生成链路和构建链路。
4. 开发完成后跑 `pnpm docs:generate` 与 `pnpm docs:build`。
5. 自测通过后，再回写文档、进度和开发笔记。

## 关键判断

### 1. 先做站点级默认能力，不先做页面级花哨能力

这一轮没有先做“每个页面一张专属分享图”。

原因很明确：当前最缺的不是精细化，而是基础能力。

所以 M6 先补的是：

- canonical
- Open Graph
- Twitter Card
- robots.txt
- manifest
- sitemap
- 默认分享图

先把这些站稳，后面再谈页面级精修。

### 2. SEO 资产继续挂在当前生成链路上

我没有另起一套独立脚本专门维护站点 URL 列表。

这一轮继续复用当前已经稳定的页面生成结构，让 SEO 资产从现有结构里长出来：

- 页面 URL 继续来自当前站点页面
- sitemap 继续基于现有页面结构生成
- robots、manifest、默认分享图由生成脚本统一输出

这样做的好处是：后续页面结构变化时，SEO 资产也会跟着主链路更新。

### 3. 分享和搜索要共用同一份站点真值

这轮我把站点级 SEO 基础信息收口到一份独立的 `site-seo.mjs` 中。

这样 canonical、og:url、默认分享图地址和站点 URL 都来自同一份配置，而不是散落在多个地方。

这会让后续继续扩分享图和页面级 SEO 时更稳。

## 这轮代码上发生了什么

### 站点开始输出统一的分享头信息

在 VitePress 配置层，这轮已经补齐了站点级的 canonical、Open Graph 和 Twitter Card。

这意味着：

- 首页能更稳定表达站点身份
- demo 页和内容页也开始具备基础分享信息
- build 后的 HTML 里可以直接看到这组 head 元信息

### build 产物里开始有 SEO 静态资产

这一轮新增了三类站点级静态资产：

- `robots.txt`
- `manifest.webmanifest`
- 默认分享图 `site-default.svg`

这些资源都继续挂在当前的生成链路里，而不是单独维护。

### sitemap 开始稳定进入构建产物

这一轮之后，build 产物里已经稳定包含 sitemap。

这一步非常关键，因为它意味着站点结构不再只是“页面自己能打开”，而是开始被明确组织成一个可以被搜索系统理解的结构。

## 自测

这一轮继续使用统一的最小闭环自测：

```bash
pnpm docs:generate
pnpm docs:build
```

这轮除了命令通过，我还重点检查了这些点：

- `docs-site/public/robots.txt` 是否生成。
- `docs-site/public/manifest.webmanifest` 是否生成。
- `docs-site/public/og/site-default.svg` 是否生成。
- `docs-site/.vitepress/dist/` 中是否出现 sitemap。
- 首页和 demo 页的构建 HTML 中是否出现 canonical、OG、Twitter 元信息。

这一轮自测通过，新的 SEO 与分享能力没有破坏现有内容生成链路。

## 这一轮的结论

M6 最重要的变化，不是“多了几个 SEO 文件”，而是站点对外的表达开始稳定了：

> 站点不只是内部能浏览，也开始具备被搜索系统和分享系统理解的基础条件。

这意味着项目从“内容和导航站”继续推进到了“可见性基础设施站”。

## 后续方向

M6 到这里已经完成。下一步自然可以继续往更深的外部可见性和内容包装推进，例如：

1. 继续做页面级专属分享图，而不只是站点默认分享图。
2. 补更细的结构化数据，让内容页、demo 页和专题页各自表达更清晰。
3. 把发布链路和站点对外分发能力继续往自动化方向推进。
