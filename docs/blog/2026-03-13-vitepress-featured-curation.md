# 2026-03-13 · 让首页精选从顺序截取变成 metadata 驱动编排

## 背景

前两轮我已经把 demo metadata 逐步整理成了三层：

- 默认提取
- 目录 preset
- 单文件 override

但首页精选区仍然保留着一个明显的过渡状态：它只是从每个分类里按顺序截前几个 demo。

这种做法短期能用，但问题很直接：

- 它反映的是数据排列顺序，不是内容优先级。
- 首页出现哪些 demo，并没有清晰意图。
- 即使 metadata 已经变得更可读，首页仍然不像一个“被策展过”的入口。

## 这次判断

这轮我做的判断是：

> metadata 的价值不只在修正文案，还在于驱动首页编排。

也就是说，首页精选应该明确回答“为什么是它”，而不是默认把前几条塞进去。

## 实现方式

### 1. 给 metadata 增加 featured 字段

我在 metadata 里加入了 `featured`，目前主要承接两个信息：

- `priority`
- `reason`

`priority` 负责排序，`reason` 负责解释推荐理由。

### 2. 让首页精选优先消费显式标记

生成首页时，我不再简单从分类里截前几个，而是先收集所有显式标记为 featured 的 demo，再按优先级排序。

如果精选数量不够，再用稳定规则补足。

这样首页精选就从“顺序结果”变成了“策展结果”。

### 3. 把推荐理由展示出来

我还顺手把首页精选卡片补了一层推荐理由展示。

这一步虽然很小，但它让首页精选的语义明显变强了：

- 用户看到的不再只是标题。
- 用户还能知道这个 demo 为什么值得先点开。

## 这轮我更确定的一点

我越来越确定，demo 展示站的演进路径不是“页面越来越多”，而是“metadata 越来越能表达展示意图”。

只有当 metadata 能表达：

- 这是什么
- 它适合谁
- 为什么值得先看

首页和分类页才会真正像一套内容系统。

## 自测

这轮我还是按生成和构建两层验证：

```bash
cd docs-site
node scripts/generate-demo-pages.js
npm run build
```

重点检查：

- featured 是否按优先级排序。
- 首页卡片是否显示推荐理由。
- 没有 featured 的 demo 是否仍然能安全生成。

## 后续

如果这层继续稳定，下一步最自然的两个方向是：

1. 给首页精选增加分类配额和更细的编排规则。
2. 继续扩展截图、封面图和推荐标签，让首页更像真正的 showcase。
