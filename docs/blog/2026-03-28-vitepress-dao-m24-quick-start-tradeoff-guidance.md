# 2026-03-28 · 让 quick start 开始解释为什么先补这一类

## 背景

M23 完成之后，quick start 已经开始告诉用户：

- 下一步该补什么
- 当前先不上什么更稳

这让 quick start 的继续推进判断已经更完整了。

但新的缺口也很快变得很清楚：

> 当用户已经知道补什么 / 不补什么之后，他还是不容易判断，为什么当前先补 A，而不是 B。

这就是 M24 要继续补上的语义。

## 这一轮怎么推进

这一轮继续按 Dao 节奏推进：

1. 先确认 M24 仍然沿着 quick start 主链路走，不新增复杂系统。
2. 梳理当前已具备的 follow-up 和 defer 字段，确认还缺“为什么这样排顺序”的说明层。
3. 定义新的轻量字段：`tradeoffNotes`。
4. 让 quick start 详情页开始表达“为什么当前先补这一类”。
5. 让角色页、阶段页与推进类型页开始聚合常见取舍判断。
6. 把这层轻量取舍提示接回首页、discover 与 quick start 总览。
7. 开发完成后跑 `pnpm docs:generate`、`pnpm docs:build`、`pnpm docs:check`。

## 关键判断

### 1. 这一轮不做复杂决策树，只补最稳定的取舍说明

M24 没有开始做动态推荐，也没有把 quick start 拉成复杂流程树。

因为当前最稳定的问题不是“推荐不够智能”，而是：

- 用户知道了方向
- 但还不知道当前为什么这样排顺序

所以这一轮只补最稳定的一层取舍说明。

### 2. 继续复用 quick start 主链路，不另建新模型

这一轮没有另外建“对比推荐系统”。

而是继续把推进取舍写回 `quickStartGuides`：

- `tradeoffNotes`

每条说明都只回答三件事：

- 当前先补哪一类
- 当前先不上哪一类
- 为什么这样排顺序

这样 quick start 的判断链还是一条主线，而不是突然长出另一套规则树。

### 3. “为什么这样取舍”比再多一个入口更能帮助用户做决定

M20 解决的是下一步去哪。
M21 解决的是下一步属于哪一类。
M22 解决的是这一步对角色 / 阶段意味着什么。
M23 解决的是当前先不上什么。

M24 继续往前推进一层：

- 为什么当前先补 A，而不是 B

这会让 quick start 不只是不断加提示，而开始真正表达优先级判断。

## 这轮代码上发生了什么

### quick start 统一补了推进取舍字段

这一轮为 quick start 统一补齐了：

- `tradeoffNotes`

这样每条 quick start 不只会表达：

- 下一步该补什么
- 当前先不上什么

也开始表达：

- 为什么当前先补这一类
- 为什么现在不是先补另一类

### quick start 详情页开始表达“为什么当前先补这一类”

这一轮最直观的变化，是 quick start detail 页新增了新的取舍说明区块：

- 为什么当前先补这一类

这个区块会直接把：

- 当前优先方向
- 当前暂缓方向
- 取舍原因

放在一起说明。

### 角色页、阶段页和推进类型页开始聚合取舍说明

这一轮还把取舍说明继续接回聚合页。

现在在：

- 角色页
- 阶段页
- 推进类型页

用户都能看到一层更轻量的常见取舍判断，而不只是单纯的入口清单。

这样这些页面开始更像判断入口，而不只是导航层。

### 首页、discover 与 quick start 总览一起接入了轻量取舍提示

为了不把这层说明只留在 detail 页里，这一轮也把取舍提示接回了入口层。

现在用户在：

- 首页
- discover
- quick start 总览

都能更早看到一些典型判断，例如：

- 为什么当前先补内容入口，而不是先补局部动效
- 为什么当前先补反馈节奏，而不是先补首屏氛围

M24 最重要的变化，不是又多了一层字段，而是：

> 当前 quick start 已开始具备静态推进取舍说明能力，能把继续推进判断解释成更清楚的优先级选择，而不只是列出方向。

这会让 quick start 更像真正的判断链，而不是越来越长的入口集合。
