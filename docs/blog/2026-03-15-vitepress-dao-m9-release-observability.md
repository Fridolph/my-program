# 2026-03-15 · 让发布结果开始拥有可回看的状态快照

## 背景

M8 完成之后，站点已经具备：

- 页面级分享卡片
- 更细的传播语义
- 稳定的生成链路

但如果从维护者视角继续看，会发现还有一个问题没有真正补齐：

> 发布已经可校验了，但发布之后“当前到底发布了什么状态”这件事，仍然主要散落在 workflow 日志和人的记忆里。

也就是说，发布链路虽然越来越清楚，但“发布状态”本身还没有变成站点可回看的事实。

所以 M9 这一轮，我继续沿着 Dao 的节奏往前推：

> 让发布结果开始拥有可回看的状态快照，也让回滚判断开始有稳定基线。

## 这一轮怎么做

这一轮继续按统一节奏推进：

1. 先定义 M9 的目标、边界和业务流。
2. 明确发布快照、发布状态页与回滚基线三类对象。
3. 再把快照 JSON、状态页和 workflow 摘要输出一起落下去。
4. 开发完成后跑 `pnpm docs:check`，并模拟检查发布摘要逻辑。
5. 自测通过后，再回写设计、任务、进度和开发笔记。

## 关键判断

### 1. 先让发布事实变成产物，再谈更深的观测

这一轮没有直接接第三方监控，也没有做自动回滚。

原因很简单：如果连“当前构建的关键统计是什么”都没有稳定产物，那更深的观测只会建立在更不稳的地基上。

所以这一轮先补的是最基础、也最关键的一步：

- 生成发布快照
- 生成发布状态页
- 在 workflow 中显式输出摘要

### 2. 发布状态页不该是第二套人工文档

如果状态页靠手写，它很快就会和真实构建产物脱节。

所以这轮的设计判断是：

```text
生成链路
  -> release-manifest.json
  -> /guide/release-status
  -> workflow 摘要输出
```

也就是说，站内状态页不再是“另外维护的一页说明”，而是直接从发布快照长出来的。

### 3. 回滚基线要绑定关键产物，而不是停留在口头经验

这轮没有做自动回滚，但我把回滚前该看什么先写成了明确线索：

- `pnpm docs:check`
- `release-manifest.json`
- 关键发布产物是否存在
- 最近一个已知通过的主分支提交

这样做的意义是：后续就算要继续做自动化，也不会从零开始讨论“到底先看什么”。

## 这轮代码上发生了什么

### 新增了发布快照文件

这一轮新增了 `/release-manifest.json`。

它会记录当前构建的关键统计，例如：

- demo 数量
- 分类数量
- 标签与场景数量
- 开发笔记数量
- 站点路由数量
- 页面级分享图数量
- 关键发布校验项

这让发布状态第一次变成了可被直接读取的静态产物。

### 新增了站内发布状态页

这一轮新增了 `/guide/release-status`。

这页的重点不是“解释发布原理”，而是帮助维护者快速回看：

- 当前构建快照
- 当前发布命令
- 当前关键校验项
- 当前重点回看路由
- 当前回滚基线

这让发布说明和发布状态开始分工明确：

- `/guide/deployment` 负责说明“怎么发”
- `/guide/release-status` 负责说明“现在是什么状态”

### workflow 开始输出发布摘要

这一轮 workflow 继续保留现有校验链路，但额外做了两件事：

1. 校验 `release-manifest.json` 已进入构建产物。
2. 从快照中读取关键字段并打印到日志。

这样一来，workflow 的结果就不再只是“通过 / 失败”，而开始附带当前发布状态的核心上下文。

## 自测

这一轮继续用统一最小闭环做自测：

```bash
pnpm docs:check
```

除此之外，我还额外做了三类检查：

1. 检查 `docs-site/public/release-manifest.json` 是否稳定生成。
2. 检查 `/guide/release-status` 页面是否已经生成并可回看。
3. 本地模拟检查 workflow 读取快照并输出摘要的逻辑是否正常。

这轮自测通过，说明发布快照、状态页和 workflow 摘要三条线已经闭环。

## 这一轮的结论

M9 最重要的变化，不是“又多了一页指南”，而是发布这件事终于开始拥有属于自己的状态表达：

> 发布不再只是一次构建动作，而开始拥有可被查看、可被解释、可用于回滚判断的状态快照。

这意味着站点的工程化已经从“能发、会校验”继续走到“发布结果本身可回看”的阶段。

## 后续方向

M9 到这里已经完成。后续自然还可以继续推进，例如：

1. 把静态快照继续扩展到更细的发布历史或版本轨迹。
2. 在合适的时候接入更外层的监控、告警或自动回滚能力。
3. 继续削弱旧入口和历史目录的认知权重，让新主站语义更集中。
