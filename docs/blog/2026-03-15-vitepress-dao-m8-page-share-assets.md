# 2026-03-15 · 让每个关键页面开始拥有自己的传播语义

## 背景

M7 完成之后，站点已经具备：

- 稳定的发布说明
- 可校验的 workflow
- 更统一的新旧入口认知

从站点工程这条线看，已经比较顺了。

但我继续往外看，会发现还有一个很直观的问题没有真正解决：

> 当别人分享首页、分享某个 Demo、分享某篇开发笔记时，外部平台看到的还是几乎同一套默认分享图。

这意味着站点虽然已经“能分享”，但还没有真正进入“按页面表达自己”的阶段。

所以 M8 这一轮，我继续按 Dao 的节奏往前推了一步：

> 让页面级分享图进入生成链路，让关键页面开始拥有自己的传播语义。

## 这一轮怎么做

这一轮继续按统一节奏推进：

1. 先定义 M8 的目标、边界和业务流。
2. 明确分享图模板、route 映射与 fallback 三类对象。
3. 再把页面级 SVG 资产生成、映射文件和 VitePress head 接入一起落下去。
4. 开发完成后跑 `pnpm docs:check`，并检查关键页面的 `og:image` 是否已经区分开。
5. 自测通过后，再回写设计、任务、进度和开发笔记。

## 关键判断

### 1. 不再让分享图停留在站点级默认能力

M6 已经把 canonical、OG、Twitter Card 和默认分享图补上了。

但那一轮解决的是“有没有”，不是“够不够表达页面差异”。

所以这一轮的判断很明确：

- 首页要有首页的语义
- Demo 页要有 Demo 页的语义
- 开发笔记要有开发笔记的语义
- 指南页和多维导航页也应该有自己的表达

也就是说，分享图要开始跟着页面内容走，而不是只跟着站点走。

### 2. 先把分享图变成生成资产，再让 head 去消费

这一轮我没有把逻辑写成一堆 `if/else` 散在 `config.ts` 里。

而是先把链路拆清楚：

```text
页面数据
  -> 生成 SVG 分享图
  -> 生成 route 映射
  -> transformHead 读取映射
```

这样做的好处很直接：

- 页面级分享图会真实出现在产物里
- 本地生成与线上构建保持一致
- 以后继续扩展到 PNG、截图或更复杂模板时，不需要推翻现在的结构

### 3. 优先覆盖关键页面，而不是一开始就追求极致复杂

这一轮重点覆盖的是：

- 首页
- 指南页
- 专题发现页
- 多维导航页
- 分类页
- Demo 页
- 开发笔记页

未命中的页面继续回退到默认分享图。

这个判断很重要，因为它让这一轮的工作量和收益是平衡的：

- 关键页面先有明确提升
- 整站稳定性不被牺牲
- 后续继续扩展时也有清晰边界

## 这轮代码上发生了什么

### 分享图生成正式接入内容主链路

这一轮把页面级分享图生成直接挂到了 `generate-demo-pages.js` 上。

这样页面、内容和分享图不再是三条分开的线，而开始变成一条链：

```text
内容元信息
  -> 页面生成
  -> 分享图生成
  -> head 引用
```

这比人工维护一堆静态图可靠得多。

### 新增了 route 到分享图的映射文件

这一轮新增了 `.vitepress/generated/page-seo.mjs`。

它的意义很大，因为它把“哪个页面对应哪张图”从隐性规则变成了显性数据。

之后如果要排查某个页面为什么命中了某张分享图，不需要再去猜，只要看映射文件就行。

### VitePress 的 head 逻辑开始读取页面级映射

`transformHead` 现在不再一律返回默认分享图。

它会先按页面 route 查映射，如果找到了页面级资产，就输出对应的 `og:image` 和 `twitter:image`；如果没找到，再回退到默认图。

这一步让页面级表达和整站稳定性同时成立。

## 自测

这一轮继续用统一最小闭环做自测：

```bash
pnpm docs:check
```

除此之外，我还额外做了三类检查：

1. 检查 `docs-site/public/og/generated/` 是否已经生成关键页面分享图。
2. 检查首页、Demo 页和开发笔记页构建后的 HTML 中是否已经命中不同的 `og:image`。
3. 检查未命中映射时是否仍会回退到默认分享图。

这轮自测通过，说明页面级分享资产链路已经是完整闭环。

## 这一轮的结论

M8 最重要的变化，不是“多了一批 SVG 文件”，而是站点对外传播这件事，终于开始和页面内容发生对应关系了：

> 页面不再只是被统一包装进一个站点外壳里，而开始拥有自己的传播语义。

这意味着站点已经从“有分享基础设施”继续走到“分享能力开始内容化”的阶段。

## 后续方向

M8 到这里已经完成。后续自然还可以继续推进，例如：

1. 为重点页面补更细的视觉模板分层，而不是继续共用同一种卡片布局。
2. 在条件合适时评估截图型或 PNG 型分享图产物。
3. 把页面级传播资产继续和发布可观测性、内容质量治理结合起来。
