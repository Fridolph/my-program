# 2026-03-21 · 让 quick start 开始接住第一版之后的下一步

## 背景

M19 完成之后，quick start 已经可以帮助用户：

- 按问题开始
- 按角色开始
- 按阶段开始

用户已经更容易找到适合自己的第一条起步线。

但新的缺口也变得很清楚：

> 当用户已经跑出第一版之后，站点还不能明确告诉他“下一步应该接哪一条 quick start”。

这就是 M20 的起点。

## 这一轮怎么推进

这一轮继续按 Dao 节奏推进：

1. 先定义 M20 的目标、边界和串联模型。
2. 梳理 quick start 当前哪些字段已经能支撑“第一版完成后的继续推进”。
3. 再补 `followUpSlugs` 和 `followUpReason`。
4. 接着让 quick start 详情页开始出现“做完第一版后，下一步建议”区块。
5. 然后把 quick start 总览、首页和 discover 一起接上推进表达。
6. 开发完成后跑 `pnpm docs:generate`、`pnpm docs:build`、`pnpm docs:check`。
7. 自测通过后，再回写设计、任务、进度、路线图和开发笔记。

## 关键判断

### 1. 这一轮只做静态串联，不做复杂流程系统

M20 没有引入用户状态，也没有引入动态工作流引擎。

因为当前阶段最稳定、最容易维护的，是一层静态串联：

- 这一条 quick start 跑通第一版之后，通常下一步接哪一条

它已经足够帮助用户继续推进，但又不会把 quick start 拉成一套难维护的流程系统。

### 2. 串联建议不能只有链接，还要告诉用户为什么接

如果只给出下一条 quick start 链接，用户还是不知道为什么要跳过去。

所以这一轮串联至少补了两层信息：

- 下一步接哪一条 quick start
- 为什么这一条值得继续接

这样用户看到的不是单纯的“相关推荐”，而是更贴近推进逻辑的下一步建议。

### 3. quick start 开始承担“接住第一版之后的推进”职责

M16 解决的是“从哪里开始”。
M17 解决的是“开始之后先做什么”。
M18 解决的是“值不值得现在做”。
M19 解决的是“谁来做、现在处在什么阶段做”。

M20 则继续往前推进一层：

- 第一版做完之后，下一步往哪里接

这让 quick start 更像一条持续推进的起步链，而不只是单点入口。

## 这轮代码上发生了什么

### quick start 统一补了 follow-up 串联字段

这一轮为现有 quick start 统一补齐了：

- `followUpSlugs`
- `followUpReason`

这样每条 quick start 不只回答“现在从哪里开始”，也开始回答：

- 第一版完成后，常见的下一步是什么
- 为什么下一步值得继续接

### quick start 详情页开始表达下一步建议

这一轮最核心的变化，是让 quick start 详情页开始出现新的推进区块：

- 做完第一版后，下一步建议

这个区块同时给出：

- 继续推进的判断说明
- 对应的下一条 quick start 入口

这样用户在跑完第一版之后，不需要重新回到站点入口重新判断。

### quick start 总览、首页与 discover 开始表达推进顺序

这一轮还把推进表达同步接回了入口层。

现在除了详情页，以下位置也开始表达“做完第一步后继续去哪里”：

- quick start 总览页
- 首页
- discover

这样用户第一眼就能意识到：

> quick start 不只是一个起点列表，它也开始具备继续推进的顺序感。

## 自测

这一轮继续使用统一闭环：

```bash
pnpm docs:generate
pnpm docs:build
pnpm docs:check
```

除此之外，我额外人工抽查了四件事：

1. quick start 详情页是否已经出现稳定的下一步建议区块。
2. 下一步建议是否真的能回流到下一条 quick start。
3. quick start 总览、首页和 discover 是否已经出现推进表达。
4. sitemap、release 状态与页面生成链路是否仍保持稳定。

这轮自测通过，说明 M20 已经完成了从“找到起步线”到“第一版之后继续推进”的闭环。

## 这一轮的结论

M20 最重要的变化，不是多了几段 follow-up 文案，而是：

> 当前 quick start 已开始具备静态串联能力，能帮助用户在第一版之后继续推进，而不只是停在入口判断。

这对内容站很重要。

因为真正有效的入口，不只是把用户送进来，还要在他完成第一步之后，继续帮他接住下一步。

M20 把这件事继续往前推了一步。

## 后续方向

M20 到这里已经完成。后续自然还可以继续推进，例如：

1. 继续补更细的 follow-up 语义，比如“先补结构”与“先补反馈”的不同推进线。
2. 继续把角色、阶段和 follow-up 交叉起来，形成更稳定的静态推进链。
3. 在串联能力稳定之后，再评估是否要做更强的路线编排或更细的推荐层。
