# 2026-03-15 · 继续扩路线密度，也把长尾场景讲清楚

## 背景

M14 完成之后，专题路线已经可以回流到 demo 详情页。

这一步很重要，因为它让 spotlight 不再只是 discover 上层入口，而开始变成 demo 页的解释语境。

但继续往下看时，新的问题也很清楚：

> 路线已经开始成立了，可路线还是偏少，很多长尾 scene 也还没真正被讲清楚。

尤其是在 `/explore/scenes/` 里，一部分长尾 scene 已经能访问，但还只是“挂着一个 demo”，还不够像真正的内容入口。

这就是 M15 的起点。

## 这一轮怎么推进

这一轮继续按 Dao 节奏推进：

1. 先定义 M15 的目标、边界和业务流。
2. 梳理哪些长尾 scene 值得先补 narrative。
3. 再扩一批更贴近作品集、人物入口和图片浏览的 spotlight 路线。
4. 接着同步首页路线入口密度，让入口层也跟上路线扩容。
5. 开发完成后跑 `pnpm docs:check`，确认生成、构建和校验都通过。
6. 自测通过后，再回写设计、任务、进度和开发笔记。

## 关键判断

### 1. 先补 scene 的解释层，而不是继续加功能层

当前站点已经具备：

- 分类入口
- 多维导航
- 专题路线
- demo 深描
- 路线回流

所以这一轮没有继续去做检索、推荐或更复杂的交互。

优先补的是另一层：

> 长尾 scene 到底能不能解释“为什么从这里开始”。

这一步补上之后，scene 页才会真正像内容入口，而不是只是在展示它挂了几个 demo。

### 2. 先补路线密度，而不是平均补所有 scene

这一轮没有平均补全站。

优先补的是已经能形成小型主题关系的场景，例如：

- 作品集列表
- 图文悬停预览
- 成员展示
- 人物卡片入口
- 作品集导航
- 大图预览入口
- 图片浏览
- 长文阅读
- 页面滚动反馈

这些 scene 单独看都不大，但一旦被放回路线里，就会立刻更有解释力。

### 3. 入口密度要和路线密度一起长

如果新增了路线，但首页还是只展示最少的三条，用户还是感受不到路线扩容的效果。

所以这一轮除了补内容，也同步补了首页路线入口密度，让首页可以承接更多 spotlight。

## 这轮代码上发生了什么

### 长尾 scene narrative 开始成片出现

这一轮把一批长尾 scene 的 narrative 写回了 `sceneNarratives` 主链路。

这意味着对应 scene 页已经开始稳定显示：

- 为什么从这里开始
- 什么时候从这里进入
- 挑选建议

scene 页因此不再只是列表，而开始具备“解释为什么这样浏览”的能力。

### 新增了两条更贴近预览与浏览节奏的路线

这一轮新增了两条路线：

- `portfolio-preview-entry`
- `gallery-loading-flow`

它们解决的是两个更具体的问题：

1. 作品集、人物入口和大图预览如何串成一条完整路线。
2. 图片浏览、预加载和资源进入节奏如何被放在同一条线上比较。

这让 spotlight 开始不只覆盖大类主题，也开始覆盖更具体的浏览路径。

### 首页开始承接更多路线入口

这一轮还同步调整了首页专题路线入口的展示数量。

这件事不大，但很关键：

> 路线层真正扩了，入口层也必须能看见这件事。

否则路线扩容只会停留在 discover 内部，而不会反映到首页的第一层判断上。

## 自测

这一轮继续使用统一闭环：

```bash
pnpm docs:check
```

除此之外，我额外人工抽查了几类页面：

1. 新增 spotlight 是否都已稳定生成。
2. `成员展示`、`作品集列表`、`图片浏览` 等长尾 scene 页面是否已出现 narrative。
3. 首页是否已经显示更多专题路线入口。
4. discover、scene、demo 与 journal 之间的联动是否仍保持稳定。

这轮自测通过，说明 M15 已经完成了从“路线能回流”到“路线继续扩容、长尾 scene 也开始被讲清楚”的闭环。

## 这一轮的结论

M15 最重要的变化，不是“多了几条路线”，而是：

> 当前站点开始在场景层建立更稳定的进入理由，路线和 scene 的解释层一起变厚了。

这对内容站很重要。

因为当内容继续增长时，真正决定体验的，不只是：

- 有没有入口

而是：

- 入口是否能解释自己
- scene 是否能解释为什么先看这里
- 路线是否能承接这些 scene

M15 把这三件事往前推到了一起。

## 后续方向

M15 到这里已经完成。后续自然还可以继续推进，例如：

1. 继续扩充更细粒度的 spotlight 路线，覆盖更多长尾主题。
2. 继续补剩余长尾 scene narrative，让场景页密度更均匀。
3. 在路线、scene 和 demo 解释层更稳定之后，再评估是否补更强的检索或推荐机制。
