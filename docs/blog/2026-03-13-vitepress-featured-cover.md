# 2026-03-13 · 给首页精选补一层轻量封面策展

## 背景

上一轮我已经把首页精选改成了 metadata 驱动编排，解决了“为什么推荐”的问题。

但站点首页还有一个明显短板：

- 精选卡片逻辑已经是策展式的。
- 可是视觉表达仍然很像文档列表。
- 用户第一眼看到的仍然 mostly 是文字，而不是作品感。

这说明首页精选虽然已经有了“内容选择”，但还缺一层“视觉开场”。

## 这次判断

这轮我没有直接上截图系统，而是先做了更轻量的 cover metadata。

原因很简单：

- 截图系统会引入额外的生成、存储和更新成本。
- 当前阶段更需要先验证“metadata 是否足以驱动视觉层”。

所以这次的判断是：

> 先用 cover metadata 建立首页视觉策展层，再决定是否要走更重的截图流水线。

## 实现方式

### 1. 给 metadata 增加 cover 字段

我在 metadata 中新增了 `cover`，支持两种类型：

- `gradient`
- `image`

当前主要先用 `gradient`，因为它最轻量，也最适合快速拉开卡片之间的视觉差异。

### 2. 让首页精选卡片新增封面区

首页卡片顶部现在会渲染一个 cover hero：

- 有封面配置时，显示定制封面。
- 没有封面配置时，回退到统一样式。

这样一来，精选区就不再只是文本列表，而更接近作品集式入口。

### 3. 封面和推荐理由分层

我刻意让 cover 和 featured 分开：

- `featured` 负责“为什么推荐”
- `cover` 负责“第一眼看到什么”

这两个字段组合起来，首页精选才同时具备策展逻辑和展示感。

## 我觉得最值的一点

这轮最有价值的地方，不是封面更好看，而是 metadata 终于开始同时驱动：

- 排序
- 文案
- 视觉层

这意味着首页已经不再只是生成结果的容器，而开始变成一个真正可以被“编排”的展示入口。

## 自测

这轮我还是保持相同的验证方式：

```bash
cd docs-site
node scripts/generate-demo-pages.js
npm run build
```

重点检查：

- cover 结构是否合法
- 首页精选卡片是否出现封面区
- 无 cover 配置时是否仍有稳定兜底

## 后续

如果这层 cover metadata 跑稳，下一步最自然的方向是：

1. 给 cover 增加更真实的截图资源支持。
2. 让分类页也能消费推荐封面。
3. 把首页从单层精选区继续升级成更完整的 showcase 编排。
