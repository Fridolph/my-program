# 2026-03-15 · 让 demo 页开始真正承担内容解释职责

## 背景

M9 完成之后，站点已经具备：

- 发布状态快照
- 页面级传播语义
- 更完整的发布与回滚基线

从工程链路看，已经越来越稳了。

但如果回到用户真正会读的页面，会发现还有一个很实际的问题：

> 很多 demo 页虽然已经能看、能跳、能回流，但它本身还不够像“内容页”。

也就是说，站点有了很多入口，但 demo 详情页本身还没有完全承担起解释职责。与此同时，场景导航虽然已经存在，但很多场景仍然太稀疏，不足以成为真正的进入入口。

所以 M10 这一轮，我继续按 Dao 的节奏往前推了一步：

> 让 demo 页开始真正承担内容解释职责，也让场景导航开始更像一个可以进入的内容入口。

## 这一轮怎么做

这一轮继续按统一节奏推进：

1. 先定义 M10 的目标、边界和业务流。
2. 明确 demo 深描字段、scene narrative 和 fallback 三类对象。
3. 再把 demo 页模板增强、重点案例文案补充和场景聚合一起落下去。
4. 开发完成后跑 `pnpm docs:check`，并检查重点 demo 页和场景页的实际渲染结果。
5. 自测通过后，再回写设计、任务、进度和开发笔记。

## 关键判断

### 1. 先让重点 demo 长出内容骨架，而不是一口气重写所有条目

仓库里有 74 个 demo。

如果这一轮就试图把每一个都写成长文，结果大概率是：

- 节奏失控
- 维护成本过高
- 质量反而参差

所以这一轮我选的是更稳的路线：

- 先给重点案例补结构化内容骨架
- 让模板支持 fallback
- 再让没有补全文案的案例也至少保持可读

这样 demo 页就先从“只有一段描述”升级到“有基本解释结构”，而不是非黑即白地分成“有长文”和“没内容”。

### 2. 场景补强不能只靠多写几个 `scenes`

如果只是给更多案例打上场景字段，场景页最多只是从 1 个案例变成 2 个或 3 个案例，但仍然不够像内容入口。

所以这一轮我同时做了两件事：

- 给更多重点 demo 汇聚到更稳定的公共场景
- 给关键场景补 narrative，解释“什么时候该从这里进入”“怎么挑案例”

这样场景页才开始有“入口感”。

### 3. 详情页要继续复用 metadata 主链路

这一轮没有新建一堆散落的 Markdown 手工说明页。

我还是让内容深描继续挂在 metadata 主链路上：

```text
metadata 深描字段
  -> generate-demo-pages.js
  -> demo 页内容块
  -> scene narrative
  -> explore / discover 入口
```

这样做的好处是后续继续扩内容时，依然能保持统一生成和统一维护。

## 这轮代码上发生了什么

### demo 页开始拥有结构化内容块

这一轮为 demo 页增加了这些内容块：

- 为什么值得看
- 实现拆解
- 适用场景
- 改造提醒

这几个区块解决的是同一个问题：

用户不只是想知道“这是什么效果”，还想知道：

- 为什么应该先看它
- 应该从哪里拆
- 适合放进什么页面
- 改到业务里时要注意什么

这就是 demo 页开始承担内容解释职责的第一步。

### 重点案例补了更完整的 metadata 深描

这一轮优先补的是一批高代表性案例，例如：

- 爱心 Loading 动画
- 圆形展开菜单
- 未来派 3D 菜单
- 图片取色氛围画廊
- 滚动阅读进度条

这些案例本身就承担了首页、场景导航和开发笔记中的高频引用职责，所以先把它们讲清楚，收益最高。

### 场景导航开始形成公共场景聚合

这一轮把一些过去过于零散的案例重新聚成了更稳的公共场景，例如：

- 加载进度反馈
- 导航交互
- 图文卡片展示
- 阅读反馈
- 首屏氛围

这让场景页终于不只是“某个 demo 的别名入口”，而开始成为真正的聚合入口。

### discover 页的场景入口也收口了

这一轮我还把 `discover` 页的场景卡片改成了直接跳转到场景详情页，而不是只跳到代表案例。

这个变化很小，但意义很大：

它意味着站点不再只是不断把用户送进单个 demo，而开始允许用户先在“场景层”做判断。

## 自测

这一轮继续用统一最小闭环做自测：

```bash
pnpm docs:check
```

除此之外，我还额外做了三类检查：

1. 检查重点 demo 页是否已经渲染出新增内容块。
2. 检查重点场景页是否已经出现 narrative 与挑选建议。
3. 检查 `discover` 页中的场景入口是否已经跳到场景详情页。

这轮自测通过，说明内容深描和场景补强都已经真正进入页面生成结果。

## 这一轮的结论

M10 最重要的变化，不是“多了几段文案”，而是站点里的 demo 页开始真正长成内容节点了：

> demo 页不再只是通往原始页面的跳板，而开始承担“解释为什么值得看、怎么用、怎么改”的职责。

同时，场景导航也不再只是弱标签，而开始更像一个可以带用户进入的内容入口。

## 后续方向

M10 到这里已经完成。后续自然还可以继续推进，例如：

1. 把内容深描继续扩展到更多长尾 demo。
2. 继续补齐长尾场景，让更多场景都从“单案例入口”走向“公共问题入口”。
3. 在内容骨架稳定后，再考虑把部分重点案例继续写成更完整的教程型文章。
