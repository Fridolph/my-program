# 2026-03-16 · 让 quick start 开始承担轻量决策辅助

## 背景

M17 完成之后，quick start 已经不只是入口。

它已经开始告诉用户：

- 第一步先做什么
- 面对不同情况怎么选
- 有哪些误区先别踩

但新的问题也自然出现了：

> 用户即使知道怎么开始，还是可能卡在“这条线值不值得现在做、成本大不大、要不要先跳过”。

这就是 M18 的起点。

## 这一轮怎么推进

这一轮继续按 Dao 节奏推进：

1. 先定义 M18 的目标、边界和决策字段。
2. 梳理 quick start 详情页还缺哪几层轻量决策摘要。
3. 再补 `fitFor`、`costLabel`、`firstWin` 和 `skipIf`。
4. 接着让首页与 discover 的 quick start 卡片也开始表达投入感。
5. 开发完成后跑 `pnpm docs:check`，确认生成、构建和校验都通过。
6. 自测通过后，再回写设计、任务、进度和开发笔记。

## 关键判断

### 1. 决策摘要必须继续保持轻量

这一轮没有做复杂评估器，也没有做打分系统。

因为当前阶段最有帮助的，不是让用户填写更多信息，而是先给他一眼可判断的摘要：

- 适合谁
- 改造成本
- 第一版预期
- 何时先不上

这已经足够帮助用户做第一轮筛选。

### 2. 决策信息不能只放详情页

如果决策摘要只出现在详情页，用户还是得点进去之后才知道成本和适用语义。

所以这一轮同步把 quick start 卡片也做了增强。

这样用户在首页和 discover 第一眼就能更快判断：

> 这条线适不适合我现在做。

### 3. quick start 开始承接“先判断值不值得做”

M16 和 M17 解决的是：

- 从哪里开始
- 开始之后先做什么

M18 则往前再补一层：

- 这条线现在值不值得做

这让 quick start 从单纯的任务导览继续长成轻量决策辅助层。

## 这轮代码上发生了什么

### quick start 详情页开始具备决策摘要

这一轮为现有 quick start 统一补齐了：

- `fitFor`
- `costLabel`
- `firstWin`
- `skipIf`

生成后，详情页现在会明确告诉用户：

- 这条线更适合哪些页面和项目阶段
- 预计投入大概是什么级别
- 做完第一版应该看到什么结果
- 哪些情况下可以先不上

### 首页与 discover 的卡片开始带上“投入感”

这一轮还把 quick start 卡片的表达做得更直白：

- 用 `costLabel` 表达投入级别
- 用 `fitFor` 表达适合语义

这让卡片不再只是“几条路线 / 几个 demo”的统计说明，而开始更贴近真实判断。

## 自测

这一轮继续使用统一闭环：

```bash
pnpm docs:check
```

除此之外，我额外人工抽查了四件事：

1. quick start 详情页是否出现决策摘要与“何时先不上”区块。
2. 首页 quick start 卡片是否已经开始表达成本感。
3. discover quick start 卡片是否已经开始表达适合语义。
4. quick start 与 spotlight、scene、demo、journal 的联动是否仍保持稳定。

这轮自测通过，说明 M18 已经完成了从“知道怎么开始”到“也能更快判断要不要现在做”的闭环。

## 这一轮的结论

M18 最重要的变化，不是“又多了几段说明”，而是：

> 当前 quick start 已开始承担轻量决策辅助职责，而不只是任务导览。

这对内容站很重要。

因为真正有效的入口，不只是给你路径，还会先帮你过滤掉一部分不适合当前阶段的路径。

M18 把这件事往前推了一步。

## 后续方向

M18 到这里已经完成。后续自然还可以继续推进，例如：

1. 继续补更细的角色视角，比如设计侧、前端侧、内容侧的不同起步线。
2. 继续补更具体的项目阶段判断，比如“验证期 / 打磨期 / 上线前”对应的入口。
3. 在决策摘要更稳定之后，再评估是否需要更强的推荐或更细的任务编排层。
