# 2026-03-13 · 把首页精选封面从渐变效果推进到 SVG 资源

## 背景

上一轮我给首页精选补了 cover metadata 和渐变封面，这让首页已经从纯文字列表迈进了一步。

但继续看下去，很容易发现一个新边界：

- 纯渐变封面更像“样式增强”。
- 它还不是一个真正可以复用的封面资源。
- 如果后面想把封面带到分类页、分享图或其他场景，当前做法就有点不够用了。

所以这一轮，我继续把封面往前推进了一层：从样式效果变成真实资源。

## 这次判断

我没有直接去做位图截图，而是选择了 SVG 资源化。

原因很明确：

- SVG 天然适合脚本生成。
- 资源轻量，适合进入仓库和构建流程。
- 当前阶段需要的是“可复用封面资源”，不一定是“高成本的真实截图”。

所以这次的判断是：

> 先用 metadata 驱动 SVG 封面，把封面真正变成资产，再考虑更重的截图体系。

## 我怎么做的

### 1. 新增封面资源输出目录

我让精选封面统一生成到 `public/featured-covers/`。

这样它们会天然跟着现有 public 资源流进入站点构建结果中。

### 2. 用 metadata 生成 SVG 海报

我没有额外引入设计工具链，而是直接用脚本读取当前 featured demo 的 metadata，生成包含这些信息的 SVG：

- 渐变背景
- 分类标签
- 封面短标题
- demo 标题
- 标签 chips

这样封面资源依然完全由 metadata 驱动。

### 3. 首页优先消费 image cover

资源生成后，首页精选不再只依赖即时渐变，而是优先使用 `/featured-covers/<demo-id>.svg`。

如果资源不存在，仍然能退回 gradient cover。

## 这轮最重要的收获

这轮让我更确定一件事：

> showcase 站真正有价值的，不只是页面结构，而是那些可以被持续复用的展示资产。

当封面从“样式片段”变成“可访问资源”之后，首页编排就不再只是一次性视觉处理，而是在开始积累站点自己的展示素材。

## 自测

这轮我做了两层验证：

```bash
cd docs-site
node scripts/generate-demo-pages.js
npm run build
```

重点检查：

- `public/featured-covers/` 是否生成对应 SVG 文件
- 首页精选是否优先走 image cover
- 资源缺失时是否仍然能回退

## 后续

如果这层资源化封面跑稳，下一步最自然的方向是：

1. 给分类页推荐区也复用封面资源。
2. 为 SVG 模板增加更多版式变化。
3. 在资源化封面的基础上，再逐步引入真实截图或缩略图。
