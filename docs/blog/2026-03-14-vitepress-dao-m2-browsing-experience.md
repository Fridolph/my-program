# 2026-03-14 · 用 Dao 流程把 VitePress 展示站从“能跳转”推进到“能流转”

## 背景

M1 完成后，站点已经有了更稳定的内容语义和 metadata 治理能力。

但继续使用时，一个问题马上就会出现：

- 首页能进分类
- 分类能进详情
- 详情能看 demo

可是看完之后，用户很容易停住。

这说明页面虽然已经连接起来了，但浏览路径还没有真正成立。

所以 M2 的重点不是再加更多页面，而是先把“继续浏览”这件事补起来。

## 这轮判断

我这轮先把浏览链路拆成三个问题：

1. demo 详情页如何继续浏览。
2. 分类页如何告诉用户“先看什么”。
3. 首页除了精选和分类，还能不能多一种开始方式。

然后按这个顺序推进：

- 先补详情页
- 再补分类页
- 最后补首页

因为详情页是浏览最容易断开的地方。

## 我怎么做的

### 1. 详情页补上一条、下一条和相关推荐

我把邻接导航和相关推荐都放回了生成链路里，而不是在页面组件里临时拼。

相关推荐的规则也保持可解释：

- 同分类
- 共享 tags
- 共享 scenes
- featured 作为轻量加权

这样推荐结果不是黑盒，也方便后面继续调整。

### 2. 分类页补“如何开始浏览”

之前分类页更像一张完整清单。

这次我加了三层浏览线索：

- 先看哪些条目
- 这个分类里最常见的 tags
- 这个分类里最常见的 scenes

这样分类页开始承担“引导阅读”而不只是“列目录”。

### 3. 首页补“按场景开始”

M1 已经有了 `scenes` 字段，所以这一轮我没有另造首页配置，而是直接从已有 metadata 里抽取场景入口。

这一步的意义很直接：

- 用户现在不一定非要按技术栈开始浏览
- 也可以从“长文阅读”“加载进度反馈”“成员展示”这种使用语境进入

首页因此更像内容入口，而不是静态介绍页。

## 代码落点

这轮最关键的代码落在三处。

### `docs-site/scripts/demo-registry.mjs`

新增了几类浏览数据计算：

- demo 邻接关系
- 相关推荐
- 场景入口

这让浏览线索继续保持在数据层汇合。

### `docs-site/scripts/generate-demo-pages.js`

首页、分类页和详情页新增的浏览模块都由这里生成。

这样生成结果和内容语义继续保持一致，不会出现页面手写逻辑和 metadata 漂移。

### `docs-site/.vitepress/theme/styles/custom.css`

这一轮只补承接新浏览模块所需的样式，没有改站点整体视觉方向。

这样范围更稳，也更符合 M2“先补流转，不先补大改版”的判断。

## 自测

这轮仍然保持同一套自测闭环：

```bash
pnpm docs:generate
pnpm docs:build
```

除了生成和构建通过，我还额外抽查了三类结果：

- 详情页是否出现上一条 / 下一条和相关推荐
- 分类页是否出现入口推荐、高频 tags 和常见场景
- 首页是否出现按场景开始的入口卡片

这一轮通过后，说明浏览体验增强已经真正进入生成结果，而不只是停留在设计层。

## 这轮最重要的变化

这轮最重要的变化不是加了几个模块，而是浏览链路的角色变了：

- 首页不只是“介绍站点”
- 分类页不只是“列出条目”
- 详情页不只是“展示当前 demo”

它们开始分别承担：

- 开始浏览
- 进入主题
- 继续探索

这才是 M2 真正完成的地方。
