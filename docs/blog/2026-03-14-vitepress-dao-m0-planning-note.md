# VitePress Dao 里程碑 M0 开发笔记：先把方法立住

这一轮没有直接进入新功能开发，而是先完成了一个更基础的动作：把后续开发的推进方法先立住。

原因很明确。项目已经有展示站、生成脚本、里程碑草案和 Dao 方向文档，但如果没有统一执行流，后续每一轮开发还是会回到“先写代码，再补文档，再回忆为什么这样做”的旧节奏。

所以这次先完成了 M0。M0 不是功能里程碑，而是治理里程碑。它先定义后续每一轮都必须遵循的节奏：先规划、再梳理业务流程、再做详细设计、再开发、再自测、再回写、再按 Dao Commit 提交，最后由用户做里程碑级 squash。

这轮的主要取舍是尽量轻。没有引入额外工具，也没有引入复杂流程控制，而是用现有文档目录把协议、设计和任务三层分开。这样做的好处是成本低、可立即执行，而且能和现有 `docs/frontend/`、`docs/blog/`、`docs-site/guide/` 结构直接兼容。

自测也沿用了项目现有最小闭环：先执行 `pnpm docs:generate`，再执行 `pnpm docs:build`。这说明本轮新增的规划文档和路线图调整没有破坏已有生成和站点构建主链路。

M0 做完以后，后续推进会更顺。M1 可以在这套协议上继续做内容治理收口，M2-M4 也都能沿着同样结构展开，而不是每次重新发明流程。
