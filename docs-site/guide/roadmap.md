# 里程碑规划

这里按“能持续交付”的思路，把后续重构拆成 12 个里程碑，并先补一个治理基线阶段。


## M0 规划与治理基线

目标：先把 Dao 执行方式、里程碑节奏、文档结构和提交规范立住。

- 统一“规划 -> 流程梳理 -> 详细设计 -> 开发 -> 自测 -> 回写 -> 提交”的执行链路。
- 建立 M0-M4 的阶段总览与边界。
- 让后续每个子任务都能在文档中回看设计、过程、自测和提交记录。

验收标准：

- 后续开发有统一执行协议。
- 当前阶段和后续阶段的边界清晰。
- 当前仓库内有稳定的里程碑文档落点。

## M1 内容治理收口

目标：把现有 74 个 demo 先变成内容质量稳定的可维护资料库。

- 为重点 demo 补齐更自然的标题、描述、标签和难度。
- 增加“适用场景”“技术点”“兼容性/注意事项”等字段。
- 明确哪些 demo 属于精选、哪些适合做教程型内容。
- 梳理并收敛中文目录、历史命名与 slug 映射。

验收标准：

- 首页精选全部具备统一质量的 metadata。
- 每个分类至少完成一轮人工校对。
- 新增 demo 时不需要直接改 Markdown，只需补 metadata 即可。

## M2 浏览体验升级

目标：让站点更像“在线文档/博客”，而不是“分类目录页”。

- 增加专题页，比如“适合首页首屏的动画”“适合卡片交互的 hover 效果”。
- 在 demo 页增加上一条/下一条、相关推荐、同标签跳转。
- 把首页从静态介绍进一步升级为内容入口页。
- 视需要增加封面图、摘要卡片和分类说明模块的层次感。

验收标准：

- 首页、分类页、详情页之间形成明确的内容流转。
- 用户不依赖仓库目录，也能快速发现高价值 demo。

## M3 发布与运维标准化

目标：让展示站成为仓库默认入口，具备稳定发布能力。

- 固化 `pnpm docs:dev`、`pnpm docs:generate`、`pnpm docs:build` 开发命令。
- 补充 GitHub Pages 发布说明或 CI 工作流。
- 校验 `base`、静态资源路径和 GitHub 仓库页部署行为。
- 视情况弱化或迁移旧 `views/index.html` 的角色。

验收标准：

- 本地和线上访问路径一致可预期。
- 新提交不会破坏已有 demo 的预览和资源引用。

## M4 内容产品化演进

目标：从 demo 展示站进化成长期更新的前端灵感/实践文档库。

- 引入博客式文章，沉淀 demo 背后的实现思路与改造经验。
- 为精选专题补充图文叙述，而不是只保留 demo 卡片。
- 评估是否需要“按技术标签/按场景/按难度”的多维导航。
- 结合 SVG 封面资产，扩展到 OG Image 和分享卡片。

验收标准：

- 站点既能承载 demo，也能承载文章型内容。
- 仓库对外呈现从“代码收藏夹”升级为“内容型项目”。

## M5 多维导航与发现增强

目标：让标签、场景、难度从 metadata 字段升级为真正的站点导航结构。

- 新增多维导航总入口，统一承接标签、场景、难度三类浏览方式。
- 生成标签、场景、难度的索引页和详情页。
- 让 demo 详情页可以回流到当前案例所属的维度页。
- 让首页、专题发现和开发笔记之外，再多一条“按问题进入”的浏览路径。

验收标准：

- 站点具备稳定的 `/explore/` 多维导航入口。
- 标签、场景、难度三类页面均可访问且可回到 demo。
- metadata 不再只是说明字段，而成为导航结构的一部分。

## M6 SEO 与分享可见性增强

目标：让站点从“内部能浏览”继续推进到“对外可被搜索、可被分享”。

- 补 canonical、Open Graph、Twitter Card 等站点级分享与 SEO 元信息。
- 补 robots.txt、manifest.webmanifest 和默认分享图。
- 让 sitemap 稳定进入构建产物，表达整站结构。
- 继续复用当前内容生成链路，不另起第二套 URL 维护系统。

验收标准：

- build 产物中具备 sitemap 和站点级分享元信息。
- `robots.txt`、`manifest.webmanifest` 和默认分享图稳定输出。
- 首页、demo 页、内容页都具备统一的基础分享信息。

## M7 发布自动化与旧入口收敛

目标：让发布链路可回看、可校验，并把旧入口正式收敛到新主站语义体系。

- 新增站内发布说明页，统一收口默认入口、发布命令和关键校验项。
- 增强 GitHub Pages workflow，在上传产物前校验关键文件存在。
- 让旧入口 `views/index.html` 带有 noindex、canonical 和迁移说明。
- 让旧入口也进入发布产物，不再只停留在仓库中。

验收标准：

- 站内可以访问 `/guide/deployment`。
- workflow 能校验关键发布产物。
- 旧入口能够稳定跳转到主站，并减少双入口认知冲突。

## M8 页面级分享卡片资产化

目标：让站点从“有默认分享图”继续推进到“关键页面拥有自己的传播语义与分享卡片”。

- 生成首页、指南页、专题页、多维导航页、分类页、Demo 页和开发笔记页的页面级分享图。
- 建立 route 与分享图资源之间的稳定映射，而不是在 VitePress 配置里手工散写判断。
- 让页面级分享图进入生成链路，和 demo、journal、guide 一起被统一产出。
- 继续保留默认分享图作为 fallback，保证整站稳定。

验收标准：

- 关键页面构建后具备专属 `og:image` / `twitter:image`。
- `docs-site/public/og/` 中存在页面级分享图资产。
- 未命中映射的页面仍能回退到默认分享图。

## M9 发布观测与回滚基线

目标：让站点从“发布链路可校验”继续推进到“发布状态可回看、回滚判断有基线”。

- 生成发布快照 JSON，沉淀当前站点产物规模、关键文件和核心统计。
- 新增站内发布状态页，统一回看发布摘要、关键校验项和回滚判断线索。
- 在 workflow 中显式输出发布摘要，而不只停留在成功/失败结果。
- 继续复用现有发布命令与生成链路，不额外引入第三方观测系统。

验收标准：

- build 产物中存在发布快照文件。
- 站内可以访问 `/guide/release-status`。
- workflow 会校验并输出发布摘要。

## M10 内容深描与场景补强

目标：让站点从“有内容入口”继续推进到“demo 详情页更像文档节点，场景页更像真正的进入入口”。

- 为重点 demo 增加“为什么值得看、实现拆解、改造提醒”等结构化内容块。
- 为重点案例补更多可复用的公共场景，提升场景聚合度。
- 为关键场景补充 narrative，解释什么时候该从这个场景进入、优先看哪些案例。
- 继续复用 metadata 主链路和生成模板，不新增第二套手工维护体系。

验收标准：

- 重点 demo 页具备更完整的内容骨架。
- `/explore/scenes/` 中的重点场景开始聚合多个案例。
- 场景详情页具备更明确的进入理由和挑选建议。

## M11 构建性能与预览体验优化

目标：让站点从“入口和内容都已具备”继续推进到“构建更轻、header 更聚焦、预览验证更稳定”。

- 收掉当前高成本的本地搜索索引入口，降低构建体积告警。
- 让 header 继续围绕内容入口，而不是被搜索框挤占空间。
- 巩固 `docs:preview` 作为最终产物验证方式。
- 把当前性能判断和预览策略明确写回文档。

验收标准：

- build 不再出现本地搜索索引超大 chunk 告警。
- header 不再显示搜索框。
- 站内仍能通过首页、discover、explore 和分类页完成主要内容发现。

## M12 内容入口视觉化与封面扩展

目标：让站点从“入口结构清楚”继续推进到“入口一眼更好判断，视觉辨识度更稳定”。

- 为分类和重点场景建立统一的封面元数据与生成链路。
- 把首页、discover 和 explore 的关键入口改为更可视的封面卡片。
- 继续复用当前脚本生成体系，而不是新增手工维护页面。
- 让视觉增强服务于内容发现，不牺牲已有的信息密度。

验收标准：

- 首页分类入口具备统一视觉封面。
- discover 与 explore 的重点场景入口具备统一视觉样式。
- build 后稳定产出入口封面资源。

## M13 专题路线聚合与长尾场景收口

目标：让站点从“入口很多”继续推进到“入口之间的上层关系更清楚，长尾场景开始被主题路线承接”。

- 为相近场景建立专题路线元数据与聚合页。
- 让 discover 与首页开始承接更高层的问题路线入口。
- 继续复用 scene、tag 与 demo 生成链路，而不是新增第三套内容系统。
- 让路线页回答“为什么从这里开始、先看什么、再往哪里走”。

验收标准：

- 站内具备 `/discover/spotlights/` 专题路线入口。
- 每条路线页都能回流到 scene 详情页和 demo 详情页。
- discover 与首页已出现专题路线入口。

## M14 专题路线回流与长尾 Demo 深描扩展

目标：让站点从“有专题路线”继续推进到“专题路线真正反过来提升 demo 详情页质量”。

- 让 demo 详情页显示所属专题路线。
- 为一批已进入专题路线的长尾 demo 补齐结构化深描内容。
- 继续复用 metadata override 和页面生成链路，而不是新增手工维护分支。
- 让路线成为 demo 详情页的解释语境，而不只是入口层组织方式。

验收标准：

- spotlight 中的 demo 详情页可以看到相关专题路线。
- 一批长尾路线 demo 已补齐结构化内容块。
- 路线页与 demo 页形成稳定双向回流。

当前状态：

- 已完成路线回流区块接入。
- 已补齐一批 spotlight 长尾 demo 深描。
- 已进入开发笔记与进度文档归档阶段。

## M15 专题路线扩容与长尾场景叙述补强

目标：让站点从“路线已能回流”继续推进到“路线密度更高，长尾 scene 也开始拥有稳定解释力”。

- 新增一批更贴近作品集、人物入口和图片浏览的专题路线。

- 让首页开始承接更多路线入口，而不是继续只暴露最少数量。
- 继续复用 `site-content` 和生成主链路，而不是新增手工维护页面。

验收标准：

- 新增 spotlight 路线已经进入 discover 与生成链路。
- 一批长尾 scene 已具备 narrative 区块。
- 首页与 discover 已能承接更多路线入口。

当前状态：

- 已完成专题路线扩容。
- 已完成首页路线入口密度同步。

## M16 问题起步路线与轻量检索替代入口

- 让快速开始页承接 spotlight、scene 和 demo。

验收标准：

- 站内具备 `/discover/quick-start/` 入口。
- 快速开始详情页可回流到路线、场景与案例。
- 首页与 discover 已出现快速开始入口。

当前状态：

- 已完成首页与 discover 入口同步。
- 已进入开发笔记与进度文档归档阶段。

验收标准：

- 首页已经直接暴露具体 quick start 条目。

当前状态：

6. 接着完成 M5，把 metadata 提升为真正的多维导航结构。
7. 接着完成 M6，把站点外部可见性基础设施补齐。
8. 先推进 M7，把发布链路与旧入口认知彻底收口。
9. 先推进 M8，把页面级传播素材和分享语义资产化。
10. 先推进 M9，把发布状态快照、回滚基线和摘要输出补齐。
11. 先推进 M10，把 demo 内容解释力和场景入口密度继续补强。
12. 先推进 M11，把构建性能和预览体验继续收口。
